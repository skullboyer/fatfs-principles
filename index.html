02 / 核心模型

先记住：文件名不会直接给出数据地址

FAT 把“名字和属性”“簇的分配关系”“真正的数据字节”分开保存。读文件时，FatFs 要连续完成这几次查找和换算。

一条最重要的映射链

路径名 → 目录项（找到文件首簇和长度）→ FAT 链（找到后续簇）→ 数据区簇（换算成逻辑扇区 LBA）→ disk_read / disk_write。

A / 名字与元数据

目录保存“叫什么”

FatFs 从当前目录扫描项，比较每段名字。FAT 目录项包含属性、首簇和文件长度；长名需要 LFN 项配合短名项。

B / 分配关系

FAT 保存“下一个簇”

目录项只有起始簇。FAT[簇号] 告诉 FatFs 下一个簇在哪里，末尾用 EOC 表示结束；空闲项表示簇可分配。

C / 文件内容

数据区保存字节

文件内容写在数据簇中。簇由一个或多个扇区组成；底层驱动按 LBA 读写扇区，文件偏移仍以字节计。

D / 运行时状态

FIL 不是磁盘文件

FIL 只在 RAM 中保存当前打开状态，如 fptr、首簇和缓存。关闭后，下次仍通过目录项重新恢复首簇与长度。

缩写与术语表：第一次看 FatFs，先认清这些词
元数据描述文件的信息，例如名字、属性、起始簇、长度和时间；它不是文件内容本身。
扇区（sector）磁盘驱动读写的基本块。本例 512 B；驱动接收 LBA 和扇区数。
簇（cluster）文件系统分配空间的基本单位，由若干连续扇区组成。本例 4 个扇区，所以 2048 B。
MBR · Master Boot Record主引导记录，常见于磁盘 LBA 0；其中可有分区表。分区起始 LBA 指向卷的起点。无分区的“超级软盘”布局不一定有 MBR。
VBR · Volume Boot Record卷引导记录，位于卷起始扇区，包含引导区信息；FAT 卷的 BPB 就在这里。它描述卷内布局，不等同于整盘的 MBR。
BPB · BIOS Parameter BlockFAT 引导扇区中的参数字段集合，记录每扇区字节数、每簇扇区数、FAT 长度等；FatFs 据此计算 FAT 区、根目录和数据区位置。
LBA · Logical Block Address逻辑块地址，也就是设备可读写的逻辑扇区编号。它像“第几块”，不是文件内的字节偏移。
FAT · File Allocation Table文件分配表。传统 FAT12/16/32 用表项记录簇的后继关系或空闲状态；目录项给首簇，FAT 链帮助找到后续簇。
SFN · Short File Name短文件名，传统 8.3 名称最多 8 个主名字符和 3 个扩展名字符；FAT 目录中的短名目录项也承载属性、首簇和长度等字段。
LFN · Long File Name长文件名。FAT 用一个或多个额外目录项保存长名字符，并与后面的短名目录项关联；关闭 LFN 支持时不能按长名访问。
EOC · End Of Chain簇链结束标记。FAT 表项取 EOC 值表示当前簇是文件链末尾；具体数值随 FAT 类型而不同。
FSINFOFAT32 的空闲空间信息扇区，保存空闲簇数量、下次扫描提示等缓存信息；它不是逐簇分配表，FAT 才记录实际簇状态。
exFAT · Extended File Allocation Table面向较大存储介质的文件系统格式。它使用自己的引导参数、目录项组和分配位图；连续文件还可用 NoFatChain 标记省去逐簇 FAT 链。
FATFSFatFs 的卷上下文 C 结构（RAM 中）。挂载后保存卷布局、FAT 起点、数据区起点、缓存等运行状态；它不是磁盘上的一条记录。
FIL · File objectFatFs 的打开文件 C 结构（RAM 中），保存文件游标、簇位置、长度相关状态及缓存。FIL 不是磁盘文件本身；文件的持久元数据在目录项等磁盘结构中。
DIR · Directory objectFatFs 的目录遍历 C 结构（RAM 中），保存当前扫描位置和目录簇等状态；目录内容本身仍保存在介质的目录数据中。
FILINFO · File Information查询或枚举目录时返回给调用者的信息结构（RAM 中），例如名称、属性、大小和时间；它是结果快照，不是磁盘目录项的原样映像。
API · Application Programming Interface应用程序接口。f_mount、f_open、f_read、f_write 等是应用调用 FatFs 的公开 API。
文件偏移从文件开头数过多少字节。f_read / f_write 的长度和位置以字节表达。
缓存窗口FatFs 暂存正在查看或修改的一个扇区；被别的扇区替换前，脏数据需要写回。

每个 FAT 短目录项固定 32 字节。短名字段是 8 字节主体 + 3 字节扩展名；目录项保存属性、时间戳、首簇高低 16 位和文件大小。FatFs 扫描目录扇区并逐项比较名字；命中后从目录项取得首簇。

目录遍历是线性扫描。目录很大时会检查很多 32 B 项。FAT 长文件名由若干 LFN 项（每项最多携带 13 个 UTF-16 字符）和一个 8.3 短名项组成；仓库默认关闭 LFN，配置实验台可切换后观察额外槽位。
FAT12/16 的根目录位于固定区域，容量由 BPB 根目录项数限定；FAT32 的根目录是可扩展的簇链（本例首簇 2）。子目录在这三种 FAT 中都以簇链存储。
05 / 内存对象

运行时对象与磁盘元数据各有职责

对象不是磁盘上的 C 结构体副本。它们保存当前调用所需的指针、游标、缓存和卷参数；重新挂载时再从磁盘元数据重建这些状态。

同一文件有两套状态，不能混为一谈

磁盘上长期保存引导参数、目录记录、FAT / 位图和文件字节；RAM 中的 FATFS 保存当前卷上下文，FIL 保存打开文件的偏移与缓存，DIR 保存目录遍历位置，FILINFO 只是查询结果快照。f_sync 把修改后的内存状态写回对应磁盘元数据；关闭 FIL 不会删除文件。

          06 / 变化顺序

          创建、写入、同步、删除分别改什么

          f_mount注册 FATFS；立即挂载时读 BPB 并填写卷布局。opt=0 延迟到首个文件 API。
          f_open(create)follow_path 找父目录；名字不存在时分配目录槽，首簇和长度初始为 0。
          f_write需要数据时 create_chain 分配簇并更新 FAT；FIL 中长度和指针推进。
          f_sync / f_close写回数据缓存，更新目录项首簇、长度、时间，再同步元数据窗口和设备缓存。
          f_open(read)重新按目录项取文件首簇和长度，初始化 FIL.fptr=0。
          f_read跨簇时沿 FAT 找下一簇，按簇内偏移算 sector，再 disk_read。
          f_unlink目录项标记删除；remove_chain 清空 FAT 链并更新可用簇信息。
          数据内容删除通常不擦除旧扇区字节；簇可被新文件复用。
          同步不是事务：FatFs 按顺序写目录、FAT、FSINFO 扇区并请求设备同步；突然断电仍可能造成部分更新。掉电保护还取决于应用策略、介质行为和恢复设计。

          08 / 补齐设计细节

          主流程之外，几个关键算法决定真实行为

          生命周期时间轴讲的是一次顺序创建和读写。下面补上卷类型判定、路径匹配、目录游标、簇分配、打开模式、跨扇区读写、随机定位和空闲空间统计；这些细节解释了为什么同一个 API 会产生不同的磁盘访问。

          01 · 卷格式判定

          FAT 类型由簇数推导

          FatFs 从 BPB 计算数据簇数量，再据此判为 FAT12/16/32；exFAT 从自己的 BPB 读取簇数。

          02 · 目录游标

          目录也是可遍历的数据

          目录项按 32 B 槽排列；游标换算成字节偏移、簇、扇区和窗口位置，跨簇时才沿目录簇链移动。

          03 · 名称匹配

          文件名先命中目录记录

          follow_path 按路径分段；dir_find 从当前目录起逐项比较名称，命中后才取得首簇与长度。

          04 · 扇区 I/O

          整扇区直传，零头走缓存

          f_read/f_write 可把连续的整扇区批量交给 diskio，但不能越过当前簇边界；部分扇区通过缓存保留未覆盖的字节。

          05 · 随机定位

          文件偏移不等于簇号

          默认 f_lseek 必须从已知簇沿链走到目标；FF_USE_FASTSEEK 可构建簇链片段映射表，减少重复遍历。

          06 · 空闲空间

          计数是缓存，分配表才描述占用

          f_getfree 可能直接返回 FATFS 中有效的计数；计数无效时扫描 FAT 表项或 exFAT allocation bitmap。

          07 · 驱动边界

          FatFs 发出 LBA 请求

          ff.c 只决定读写哪个逻辑扇区；diskio.c 把请求交给平台驱动。本仓库的 diskio.c 是移植骨架，RAM/卡/USB 后端没有在这里实现。

          08 · 簇分配

          分配器会尝试减少碎片

          create_chain 会优先尝试相邻空闲簇，再从上次分配位置附近扫描空闲项。

          09 · 打开模式

          创建、覆盖、追加是不同语义

          FA_CREATE_NEW 只创建新文件；已存在时返回 FR_EXIST。其他打开标志会改变覆盖或追加行为。

          10 · 返回值

          同时检查错误码和字节数

          f_read/f_write 的实际处理字节数分别通过 br/bw 返回；到 EOF 或磁盘满时可能少于请求值。

          文件系统 API 不只有打开和读写按职责看设计
          查询f_stat 查路径元数据；f_opendir / f_readdir 顺序枚举目录；f_getfree 统计可用簇。
          命名空间f_mkdir 新建目录记录和目录簇；f_rename 改名/移动目录记录，数据簇不搬动；f_unlink 删除文件或空目录，非空目录会被拒绝。
          文件范围f_lseek 改变 FIL 游标；f_truncate 从当前位置截短并释放尾部簇；f_expand 可预分配空间。
          卷初始化f_mkfs 创建文件系统结构；f_mount 读取已有结构并建立 FATFS 上下文，两者方向相反。

          这些 API 是否能调用还受 FF_FS_MINIMIZE、FF_USE_MKFS、FF_USE_EXPAND 等编译配置控制；到配置实验区查看当前组合的 API 清单。

          理解 FAT 时要记住的边界读写语义与可靠性
          • 目录项保存属性、时间、首簇和长度；FAT 不提供 POSIX 风格的用户、组和访问控制列表。
          • FAT/exFAT 更新不是事务。f_sync 会按顺序写缓存和元数据并请求 CTRL_SYNC，但不等于日志提交或掉电原子更新。
          • 删除会移除目录名并释放簇映射，通常不覆写原数据；CTRL_TRIM 是设备提示，不是安全擦除。
          • 本页数字、目录内容、簇号和 LBA 是教学卷模型；真实介质布局和驱动返回由 BPB、分区表及平台决定。
          源码阅读路线：从公开 API 跟进内部算法

          mount_volume 解析 BPB 与数据簇数量；dir_sdi / dir_next 管目录游标和目录扩展；f_read、f_write、f_lseek 处理文件偏移；f_getfree 统计空间；sync_fs 同步卷元数据。设备契约见 diskio.h，移植模板见 diskio.c。

          10 / 总结与实践
          缩小 FatFs 与裸 Flash 的性能差距
          裸地址读写的路径更短；使用 FatFs 时，可以通过访问模式和 I/O 批量大小，减少每次传输的管理与调用开销。
          
    
          文件系统用空间和管理逻辑换取通用的文件组织；裸 Flash 用更直接的布局换取控制权，同时也接过了更多底层责任。
          
    
          
      
          1 · 合并成大块读写
          先在应用缓冲区累积数据，再一次调用 f_write 写入较大的连续块。尽量按扇区大小对齐；条件合适时按簇大小组织。这样 FatFs 和 diskio 有机会一次传输多个扇区，少做重复调用。
          
      
          2 · 保持顺序访问
          文件打开后按偏移顺序连续读写，尽量复用同一个 FIL，避免频繁关闭重开、反复查路径或在远距离偏移间跳转。已知最终文件大小且配置支持时，可考虑用 f_expand 预分配空间，减少写入时的簇分配工作。
          
      
          3 · 利用缓存局部性
          连续访问同一文件可复用 FIL 中的当前簇等定位状态；重复访问当前扇区或元数据窗口时才可能命中扇区缓存。缓存容量有限，不是大型通用读缓存；收益对重复的小块访问、部分扇区读写和元数据访问更明显。FF_FS_TINY 会改变文件数据使用独立缓存还是共享卷缓存。
          
      
          4 · 让底层保留批量传输
          检查 disk_write / disk_read 能否把多扇区请求作为一次设备传输提交。若驱动把每个请求都拆成单扇区操作，FatFs 上层批量读写带来的收益会被削弱。
          
      
          5 · 按可靠性需要同步
          不要把 f_sync 放在每个很小的数据片段后面；可在应用定义的检查点同步，并在结束时关闭文件。同步间隔越长，意外断电时可能丢失的未同步数据也越多。
          
      
          6 · 看清瓶颈在哪一层
          分别测文件打开时间、连续传输速率和同步耗时。若时间主要花在介质或设备驱动，减少 FatFs 的少量 CPU 工作不会明显提高吞吐；若小块访问占主导，批量和局部性通常更值得优先优化。
          
    
          
    
          适用范围：这些做法最能缩小“已打开文件上的连续数据传输”和裸地址读写之间的差距。首次按文件名查找、创建文件以及更新目录/FAT 元数据仍需要文件系统管理步骤；具体速率取决于介质、驱动、簇链和配置。
